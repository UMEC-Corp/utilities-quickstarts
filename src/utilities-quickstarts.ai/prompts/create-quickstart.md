Сгенерируй quickstart-сценарии **строго по описанию в задаче**.

Ответ должен быть предоставлен срого в виде JSON по шаблону:
@prompts/response-json-template.md

Перед генерацией quickstart ты ОБЯЗАН выполнить этап исследования документации.

Обязательный порядок:
1. Определи тип сценария: HTTP, WebSocket/OpenRPC или смешанный.
2. Если есть HTTP-вызовы:
   - открой портал `https://api.rumecdev.deviot.cloud/`;
   - найди карточку/ссылку нужного микросервиса;
   - перейди в документацию именно этого микросервиса (OpenAPI/ReDoc/Swagger).
3. Если есть WebSocket/RPC-вызовы:
   - изучи `https://ws.rumecdev.deviot.cloud/openrpc.json`.
4. Если сценарий смешанный (HTTP + WebSocket/RPC), используй оба источника.
5. Извлеки факты по каждому вызову: endpoint/метод (для HTTP) или RPC method (для OpenRPC), обязательные поля запроса, пример/формат ответа, коды ошибок, требования авторизации.
6. Только после этого формируй сценарии.

Критерии качества (обязательно):
- Каждый шаг с API- или RPC-вызовом в quickstart должен опираться на факты из соответствующей документации.
- Не придумывай endpoint, RPC method, payload, параметры и названия полей.
- Если по микросервису/OpenRPC не удалось открыть документацию или в ней нет нужных данных — не генерируй вымышленные шаги, а верни ошибку в JSON:
  - status: "need_clarification"
  - reason: "Не найдена/непрочитана/неполна документация нужного источника (microservice/OpenRPC)"

Источники документации (не добавлять в Markdown):
- Публичное API: `https://api.rumecdev.deviot.cloud` (для получения документации по определенному микросервису, необходимо перейти по ссылке, найти подходящую ссылку на документацию микросервис и перейти по ней).
- OpenRPC (вебсокеты): `https://ws.rumecdev.deviot.cloud/openrpc.json`.

Эндпоинты:
- Вебсокеты: `https://ws.rumecdev.deviot.cloud/ws`
- Identity: `https://http-identity.rumecdev.deviot.cloud`


Кодировка и JSON:
- Весь текст сценария и поле `body_markdown` в ответе — **UTF-8**; кириллица и символы в коде должны отображаться корректно.
