На основании **комментариев к задаче**:
- определи, какие сценарии необходимо изменить
- внеси необходимые правки в сценарии

Ответ должен быть предоставлен срого в виде JSON по шаблону:
@prompts/response-json-template.md

Перед внесением правок ты ОБЯЗАН выполнить этап исследования документации.

Обязательный порядок исследования:
1. По каждому пункту фидбэка определи тип изменений: HTTP, WebSocket/OpenRPC, Identity/OIDC или смешанный.
2. Для HTTP:
   - открой портал `https://api.rumecdev.deviot.cloud/`;
   - найди страницу нужного микросервиса;
   - дождись загрузки страницы до **30 секунд**;
   - найди и открой кнопку/ссылку на спецификацию (**Swagger/OpenAPI/API docs/Documentation**);
   - только после открытия спецификации извлеки endpoint, метод, обязательные поля, коды ошибок и требования авторизации.
3. Для WebSocket/RPC:
   - проверь `https://ws.rumecdev.deviot.cloud/openrpc.json`;
4. Для Identity (`/connect/token`, token flow, client auth):
   - используй `https://http-identity.rumecdev.deviot.cloud/.well-known/openid-configuration`;
   - используй `token_endpoint` из discovery-документа и параметры из контракта Identity.
5. Если сценарий смешанный, используй все соответствующие источники и явно разделяй, какие факты из какого источника взяты.
6. Только после подтверждения контрактов вноси правки в quickstart.

Правила правок:
- Сохраняй структуру quickstart (Цель, Предусловия, Шаги, Ожидаемый результат, при необходимости «Полный скрипт сценария»).
- Учитывай только обоснованные правки из комментариев; не выдумывай новые требования.
- Пиши только подтвержденные факты из документации: endpoint/RPC method, поля, типы и требования авторизации.
- Не оставляй в примерах псевдокод, заглушки `<...>` и непроверенные имена параметров.
- В разделе "Проверенные источники" обязательно указывай конкретные URL и фактически использованные endpoint/RPC methods.
- Если для страницы нет релевантных правок, добавлять ее в ответ не нужно.
- Если документация нужного источника недоступна или не содержит данных для корректной правки, верни JSON:
  - `status: "need_clarification"`
  - `reason: "Не найдена/непрочитана/неполна документация нужного источника (microservice/OpenRPC)"`

Запрещено:
- создавать любые файлы, скрипты, временные артефакты и директории.
- изменять/удалять существующие файлы.
- Добавлять в ответ любой текст вне JSON.
