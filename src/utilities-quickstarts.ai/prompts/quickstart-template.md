**Сценарий: <Название сценария>**

- Назвение сценария должно быть на томже языке, что и остальная часть документации

## Цель

Кратко: что пользователь получит в конце (например: «Создать заявку и отправить её на согласование»). 
- Если результатом будет получение токена/кода/идентификатора, то это также нужно указать

## Предусловия

Описываются предварительные действия/условия необходимые для выполнения сценария. Если таковых нет, указать, что пердварительных действий не требуется.
В качестве пердусловий могут быть (как пример):
- Наличие авторизации (если важна роль — укажите роль **…**, иначе роль не упоминать)
- Наличие настроек/справочников
- Прочие начальные установки
- Также допускаются ссылки на другие сценарии, чтобы не описывать повторно шаги из других сценариев. Формат: **Выполнен сценарий [Имя сценария](ссылка на md со сценарием), получен `некоторые_данные`.** 

Не нужно: 
- описывать, для каких сценарием может использовать данный сценарий
- требовать доступность API

## Шаги

Шаги описывают действия, которые необходимо совершить для достижения конечной цели.

- Шаги должны быть пронумерованы заголовками **третьего уровня**: `### 1. Краткий текст шага`, `### 2. …` 
- Если шаг предполагает использование device flow, использовать client_id="controller", grant_type="urn:ietf:params:oauth:grant-type:device_code"
- Если шаг в сценарии требует **выполнения запроса** (HTTP/WebSocket и т.п.), помимо текстового описания действия необходимо добавить **сниппет на двух языках** — **Python** и **PowerShell** — на **двух вкладках**: строки `=== "Python"` и `=== "PowerShell"` (обязательно **с двойными кавычками вокруг имени вкладки**, как в этом примере) и под каждой свой fenced-блок с кодом (заголовки вкладок только такие, без имён файлов). Содержимое каждой вкладки (включая строки с тройными бэктиками и весь код внутри) должно иметь **отступ ровно 4 пробела**. Без кавычек или без 4-пробельного отступа Confluence/MkDocs может показать строку вкладки и Markdown как обычный текст без форматирования.

## Ожидаемый результат

Описывается, итоговый результат работы сценария

- В списке появляется запись со статусом **…**
- Пользователю приходит уведомление **…** (если применимо)
- Получены некоторые даннве. Например **Получены `user_id`, `sensor_code`**

## Полный скрипт сценария

Этот раздел нужен **только если** в сценарии были **фрагменты кода**. 

- Из фрагментов нужно собрать **один связный скрипт** (на двух языках: **Python** и **PowerShell**), который можно выполнить подряд. 
- Между фрагментами вставь **комментарии**, какой пункт из раздела **«Шаги»** выполняется (например: `# Шаг 2: получение токена`). 
- Не дублируй лишнюю прозу — только рабочий код и такие пояснения. 
- Если фрагментов кода в сценарии не было, раздел **не добавляй**. 
- Всё, что нужно для запуска помимо самого кода (установка пакетов/модулей, переменные окружения, подстановка URL и токенов, важные оговорки), опиши в **Предусловиях**, **Шагах** или **Ожидаемом результате** — не прячь это в комментариях внутри полного скрипта. Но допускается оформить в скрипте набор входных парамретров и/или переменных.
